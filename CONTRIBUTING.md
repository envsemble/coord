# Working on Atlas

Keep plans, lifecycle decisions and reported outcomes in the associated planning repository, never in this one; the skills assist that workflow and the app stays a read-only local viewer. Keep semantic documents separate from capture adapters, validation, layout and React rendering. The viewer inspects models; agents/library calls author them. Stable semantic IDs survive renames. Evidence-backed snapshots remain immutable and visibly scoped. Unsupported facts use uncertainty/coverage findings rather than guessed relations or counts.

Use Node 24, npm and Java 21. Run `npm ci`, then `npm run dev` for React/Vite live updates at `127.0.0.1:5173`. The diagram package lives in `packages/diagrams`: source and UI in `lib/`, `src/` and `development/`, and the R5 model under `examples/r5`. The [architecture](docs/architecture.md), [agent](docs/agent-interface.md) and adapter guides own their contracts. The planning-folder reader shared by the app and the `atlas` command lives in `packages/planning`, and the command itself in `packages/cli`. The app lives in `app/` (run it with `npm run dev --workspace @envsemble/atlas-app`) and the agent skills in `skills/`. The planning reader and the command are TypeScript that Node 24 runs directly without a build step, so they use only erasable syntax (no enums, namespaces or parameter properties; their `erasableSyntaxOnly` setting enforces this) and `.ts` import extensions. The app is TypeScript too: its server runs through `tsx`, and Vite builds its client. The plan export viewer (`packages/planning/viewer`) reuses the app's styles and the diagram package's React viewer; `npm run build --workspace @envsemble/atlas-planning` rebuilds its committed bundle, `packages/planning/dist/plan-viewer.html`, and CI fails when the committed bundle is stale.

Run relevant capability tests while changing behavior, then `npm run format`, `npm run check:types`, `npm test`, `npm run test:skills`, `npm run build`, `npm run check` and `npm run check:package`. Commit the generated `index.html`, `downloads/` and `dist/` in `packages/diagrams` together with source. Full database verification requires `ATLAS_TEST_POSTGRES` targeting a disposable PostgreSQL 17 fixture; credentials belong in the environment, never models. Windows-specific and POSIX-specific tests disclose skips.

PR/MR descriptions should identify the behavior change, supported scope, evidence and validation. Use [revision review artifacts](docs/review-ci.md) for architecture changes, retain merge conflicts explicitly and link consequential decisions to their planning context. Human acceptance and merge stay separate from generated findings. Versioned artifacts can be checked with [release assembly](docs/releases.md); no publishing/deployment is implied. Required GitHub checks are `CI` and `Betterleaks`; the scanner is version- and hash-pinned and scans the retained Git history.

Branding sources are editable SVG in `assets/`. Screenshots, including `app/assets`, must show the actual application and have useful alternative text. Keep private source excerpts scoped and attributed. Source/asset licensing remains `UNLICENSED`; do not introduce a public license without the owner's decision.
