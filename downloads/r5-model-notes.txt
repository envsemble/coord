CONSTRAINTS
C01 — Identity separation — Platform UID, slot index/current user ID, entity handle, and network-channel identity are distinct. Reconnect and slot reuse must not silently merge them. — Source-supported distinction; temporal identity rules inferred
C02 — Slot capacity — The count of active/admitted clients must respect the configured maximum. Static slot storage is not the current lobby population. — R1, R2; proposed invariant
C03 — Fake clients — Fake-client slots need not have a remote application, network channel, or real platform account. Do not fabricate account identities for bots. — R1, R2; association policy inferred
C04 — Sign-on classification — ActiveClientSlot corresponds to sign-on state FULL. It says nothing about whether the assigned player is alive or downed. — R2 declaration
C05 — Participation scope — An assignment, participant, assigned entity, and squad must refer to the same game session. The game-session identity boundary remains inferred. — Proposed OntoUML invariant
C06 — Life and bleedout — ReadyPlayer means alive and not bleeding out; DownedPlayer means alive and bleeding out. Dead or observer entities may be in neither phase. — R12 motivates classification; stereotypes inferred
C07 — Elimination dependence — Elimination status is scoped by game session and platform identity. Registry membership, not an entity-only health predicate, determines EliminatedIdentity. — R13 observation; session boundary inferred
C08 — Respawn continuity — The inspected respawn path clears elimination and reuses a player reference. This supports script-level continuity, but does not prove native allocation or reconnect continuity. — R14 observation
C09 — Command acceptance — A received command can be declined by the movement-time wrapper. CommandProcessing denotes accepted native execution; it does not guarantee a particular gameplay outcome. — R5 observed control flow
C10 — Snapshot uncertainty — Do not impose one snapshot per frame or full-world contents from these declarations. Tick, frame, and snapshot-send interfaces are partially opaque. — R6, R7, R10 limits
C11 — Directory semantics — Listing lookup is discovery, not skill matchmaking or game admission. Hidden/public classify the listing’s hidden field; offline means no publication. — R8, R9; publication relator inferred
C12 — Version scope — Every source assertion applies to the pinned repositories supporting the named Season 3 build. Flowstate behavior can differ from original retail gameplay. — R0 and script README
