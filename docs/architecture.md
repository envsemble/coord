# Coord architecture

Coord keeps planning folders in the Coord home and shows them in the desktop app. Diagrams are files in those folders; the diagram package (`packages/diagrams`) reads, checks, captures, lays out and renders them.

The diagram package separates five concerns. **Reading** (`lib/plantuml`): a grammar for Coord's PlantUML subset, compiled with Peggy from a grammar derived from `plantuml-parser`, turns a file into statements; a reader turns them into a diagram and reports every line outside the subset; `checkDiagram` adds the model rules and the rules of the `' coord` headers, reading the files they name; `formatDiagram` writes a diagram back in its canonical form. **Capture** (`lib/capture`): adapters read code through its compiler and databases through their catalogs, and write captures in the subset. **Comparison** (`lib/payload/compareModels.cjs`): a proposal or a later capture is compared with its baseline by identity, leaving out layout and source locations. **Layout** (`lib/layout`): each diagram is laid out with orthogonal routes, a family once for all its members, and checked for overlaps and readable labels; `lib/payload` turns the laid-out diagrams into viewer payloads, `lib/render` draws their static SVG with the canvas's own components, and `lib/scenarios` assesses the scenarios that exemplify a class diagram. **Viewing** (`src`): a React viewer shows the laid-out scenes (`src/canvas`), the details of each element (`src/details`), a proposal's changes (`src/review`) and a class diagram's scenarios (`src/scenarios`), in the app (`DiagramPanel`) and in offline HTML files that `buildViewer` writes (`DiagramViewer`, both in `src/viewer`).

`describeDiagrams(files)` tells each file of a work folder its kind, role (diagram, capture, proposal or scenario), problems, baseline and family without laying anything out; `prepareDiagrams({ files, paths })` lays out the diagrams asked for, each with its family, and returns their viewer payloads. Identities come from names, so diagrams carry no IDs, revisions or coordinates; a diagram's history is its file's history in the planning folder's Git.

The coord package (`packages/coord`) has a folder per concern: `src/cli` (the `coord` command, its hooks and MCP server), `src/planning` (reading planning folders, checking them, the work operations, projects, handoffs, references and work reports), `src/home` (the Coord home and its database), `src/host` (the Coord host and its protocol) and `src/platform` (files, Git and processes). The planning reader (`src/planning/reading`) lists a work item's diagrams and links them to the headings of its documents, and the checker (`src/planning/check`) runs the diagram package's `.puml` check for `coord check` and the hooks. The desktop app reads planning folders through the Coord host, which it runs in a utility process. With remote access on, the same host serves the computer to the devices you pair. [Remote access](remote-access.md) describes its protocol, scopes and security.

Start development with `npm ci` and `npm run dev:diagrams` (the diagram viewer, showing the shop example) or `npm run dev` (the desktop app). Verify with `npm test`, `npm run check:types`, `npm run build`, `npm run check` (the examples and the committed showcase), `npm run check:package` (the packed library in a clean install) and `npm run check:performance` (a 100-class diagram through reading, checking, layout and export within its time budgets). The 1,000-node interaction fixtures establish a rendering benchmark, not a capture capacity; each adapter's limits are recorded with its fixtures.
