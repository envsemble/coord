# Learning and semester reports

The diagram remains the default. **Report** opens a native React reading view in both the dashboard and offline HTML. It contains the declared scope, revision, capture dates and coverage, guided SVG views, selected glossary/planning passages, classification rationale, open questions, evidence/excerpts and implemented validation limits. Print from the report for a light, paginated presentation; download each SVG for figures. Returning to Diagram preserves the mounted camera and selection.

An optional `learning` field contains `walkthroughs` and `scenarios`. Walkthroughs have identified titles and steps with `text`, `elementIds` and an optional explicit `viewKey`. `contextIds` references retained planning records. Scenarios have `id`, `title`, `expected: "valid" | "invalid"`, `instances: [{id, classIds}]` and `links: [{relationId, sourceId, targetId}]`, plus optional description/context. Optional `reporting: {scope, author?}` specifies submission scope. All references are checked before storage; `atlas_revise` updates these fields with the expected revision. See [the authored enrollment example](../examples/enrollment/learning.cjs).

`checkScenario(document, id)` and paginated `atlas_scenarios` assess finite examples using inherited memberships, both relation-end numeric counts and complete/disjoint generalization sets. A count beside the target is counted for each source, and vice versa. Duplicate link pairs are rejected. An unknown count, type-use dependency or textual invariant stays unassessed. Known violations can establish a counterexample even when other constraints are unassessed. Expectation mismatch is reported; it never silently changes the authored example.

These are closed-world examples over the explicitly listed population, not a general solver or a proof of domain validity. They do not establish temporal identity, rigidity, arbitrary OCL/SQL, framework behavior or implementation equivalence. OntoUML learning guidance is based on the [community specification](https://ontouml.readthedocs.io/en/latest/), including its [phase-partition constraints](https://ontouml.readthedocs.io/en/latest/classes/sortals/phase/index.html). Existing local structural/ontology rules retain their documented subset coverage.

The report and its examples are embedded in the same versioned HTML document. Reopening retains learning, scope, selected context and frozen captures. Imported dates/hashes remain preserved claims until source verification. No external assets or model service are needed to read or print the report; specification/source links are optional navigation. Keeping a plan passage in a report does not transfer ownership from its planning record.
